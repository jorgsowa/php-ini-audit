Rules

130 rules. The severity shown is the rule's default; an individual finding can be raised or lowered by context, such as the SAPI, the profile or a related setting.

Code execution #

EXEC-001Remote file inclusion enabledcritical
Category Code executionScope configWeakness CWE-98

allow_url_include lets include/require load code from http://, ftp:// and data:// URLs, turning any file-inclusion bug into remote code execution.

Directives allow_url_include, allow_url_fopen

Fix: Set allow_url_include = Off. The directive has been deprecated since PHP 7.4.

  • https://www.php.net/manual/en/filesystem.configuration.php#ini.allow-url-include
EXEC-002Remote URLs accepted by file functionsmedium
Category Code executionScope configWeakness CWE-918

allow_url_fopen lets fopen(), file_get_contents(), getimagesize() and friends fetch http:// and ftp:// URLs, which turns user-controlled paths into server-side request forgery.

Directives allow_url_fopen

Fix: Set allow_url_fopen = Off and use an HTTP client (cURL) with explicit allow-lists where remote fetches are needed.

  • https://www.php.net/manual/en/filesystem.configuration.php#ini.allow-url-fopen
EXEC-003Auto-prepended/appended file loaded through a stream wrappercritical
Category Code executionScope configWeakness CWE-94

auto_prepend_file/auto_append_file pointing at php://input, data:, http:// or another wrapper executes request- or network-supplied code on every request; this is a classic FastCGI exploitation payload.

Directives auto_prepend_file, auto_append_file

Fix: Remove the directive or point it at a root-owned local file.

EXEC-004Code automatically prepended or appended to every scriptinfo
Category Code executionScope configWeakness CWE-506

auto_prepend_file/auto_append_file run a file before/after every script. Security plugins use it legitimately, but a value set from .user.ini or .htaccess is a common web-shell persistence technique.

Directives auto_prepend_file, auto_append_file

Fix: Confirm the file is expected, root-owned and not writable by the PHP user; set user_ini.filename = to stop per-directory overrides if they are not needed.

EXEC-005Command execution functions are availablemedium
Category Code executionScope configSAPIs apache2, cgi, fpm, litespeed, unknownWeakness CWE-78

Functions that spawn processes turn code injection, deserialization gadgets and file uploads into full operating-system command execution.

Directives disable_functions

Fix: List the functions the application does not use in disable_functions (php.ini or php_admin_value in the FPM pool). Composer and symfony/process need proc_open.

  • https://www.php.net/manual/en/ini.core.php#ini.disable-functions
EXEC-006disable_functions can be bypassedmedium
Category Code executionScope configSAPIs apache2, cgi, fpm, litespeed, unknownWeakness CWE-693

With every exec-style function disabled, putenv() combined with a function that launches sendmail lets an attacker set LD_PRELOAD and run native code anyway.

Directives disable_functions

Fix: Also disable putenv and the mail launchers that are not needed, or run PHP with a seccomp/AppArmor profile instead of relying on disable_functions.

  • https://www.php.net/manual/en/function.putenv.php

  • https://www.php.net/manual/en/ffi.configuration.php

Filesystem and paths #

FS-001open_basedir is not setmedium
Category Filesystem and pathsScope configSAPIs apache2, cgi, fpm, litespeed, unknownWeakness CWE-22

Without open_basedir, a path traversal or file-inclusion bug can reach any file the PHP user can read (/etc/passwd, other sites, keys). PHP does not treat it as a hard security boundary, but it limits the impact of common bugs.

Directives open_basedir

Fix: Set open_basedir to the application directory plus its temp/session/upload directories, each with a trailing slash.

  • https://www.php.net/manual/en/ini.core.php#ini.open-basedir
FS-002open_basedir allows the whole filesystemmedium
Category Filesystem and pathsScope configWeakness CWE-22

An open_basedir entry of '/' (or a bare drive) disables the restriction entirely.

Directives open_basedir

Fix: List only the directories the application needs.

FS-003open_basedir entries match by prefixlow
Category Filesystem and pathsScope configWeakness CWE-22

open_basedir compares prefixes: '/var/www/site' also allows '/var/www/site-backup'. A trailing separator restricts the entry to that directory.

Directives open_basedir

Fix: End every directory entry with '/' (or '\' on Windows).

FS-004open_basedir uses relative entrieslow
Category Filesystem and pathsScope configWeakness CWE-22

Relative entries such as '.' are resolved against the current working directory, which changes with chdir() and the requested script.

Directives open_basedir

Fix: Use absolute directories only.

FS-005Security-relevant path is world-writablehigh
Category Filesystem and pathsScope configWeakness CWE-732

A path PHP loads code, certificates, sessions or logs from is writable by every local user, or sits in a world-writable directory where it can be created or replaced.

Fix: Make the path owned by root (or the deploy user) and not writable by others; use a dedicated directory instead of /tmp.

FS-006Sensitive path inside a web-served directoryhigh
Category Filesystem and pathsScope configWeakness CWE-538

Logs, sessions, uploads or caches under the document root can be downloaded, and log or session files that are both web-reachable and includable enable log-poisoning attacks.

Fix: Move the path outside the document root. Pass --webroot to make this check exact.

FS-007Configured path does not existinfo
Category Filesystem and pathsScope config

An explicitly configured path does not exist on the audited system; PHP silently falls back or fails at runtime, and whoever creates the path first controls it.

Fix: Create the path with the intended owner and permissions, or remove the directive.

FS-008Per-directory .user.ini overrides enabledinfo
Category Filesystem and pathsScope configSAPIs cgi, fpm, litespeed, unknownWeakness CWE-15

With CGI/FastCGI, any directory may carry a .user.ini that changes PERDIR settings such as auto_prepend_file. An upload vulnerability then becomes persistent code execution.

Directives user_ini.filename

Fix: Set user_ini.filename = (empty) if applications do not need per-directory settings.

FS-009HTTP file uploads enabledinfo
Category Filesystem and pathsScope configSAPIs apache2, cgi, fpm, litespeed, unknownWeakness CWE-434

file_uploads lets every script receive files; disable it on hosts that never accept uploads.

Directives file_uploads

Fix: Set file_uploads = Off where uploads are not needed.

FS-010Uploads stored in the shared system temp directoryinfo
Category Filesystem and pathsScope configSAPIs apache2, cgi, fpm, litespeed, unknownWeakness CWE-377

Without upload_tmp_dir, uploads land in the system temp directory shared with every other process, which eases temp-file races and LFI-via-upload techniques.

Directives upload_tmp_dir, file_uploads

Fix: Point upload_tmp_dir at a dedicated directory owned by the PHP user, mode 0700.

FS-011Configuration file writable by other userscritical
Category Filesystem and pathsScope fileWeakness CWE-732

Anyone who can write a PHP configuration file or its directory can enable auto_prepend_file, load extensions or disable protections.

Fix: Make configuration files and their directories owned by root and not writable by group or others.

Configuration hygiene #

CFG-001Syntax problem in configuration filelow

Lines PHP cannot parse are ignored or stop INI parsing at that point, so later settings silently do not apply.

Category Configuration hygieneScope file

Directives removed from PHP are ignored. Settings such as safe_mode or magic_quotes_gpc give a false sense of protection; register_globals = On is critical on the old versions that still honour it.

Fix: Remove obsolete directives and use their modern replacements.

CFG-003Unknown directive resembling a known onelow

PHP ignores unknown directive names (and names are case-sensitive), so a typo such as 'display_error' leaves the intended protection unset.

Fix: Correct the directive name.

CFG-004Directive redefined with a different valueinfo
Category Configuration hygieneScope config

When php.ini, scan-dir files and pool settings disagree, the last one read wins. Reviewers looking at only one file get the wrong picture.

Fix: Keep each security directive in one place.

CFG-005Per-directory override that PHP ignoreslow
Category Configuration hygieneScope config

.user.ini and .htaccess can only change PHP_INI_PERDIR/PHP_INI_ALL directives. Hardening attempted there for PHP_INI_SYSTEM directives (disable_functions, allow_url_fopen, expose_php, ...) does not take effect.

Fix: Move the setting to php.ini or to php_admin_value in the FPM pool / Apache vhost.

CFG-006No php.ini loaded: built-in defaults in effectmedium
Category Configuration hygieneScope config

Without php.ini, PHP runs with compiled-in defaults: display_errors = On, register_argc_argv = On, expose_php = On, enable_dl = On and no disable_functions. Official Docker images ship this way.

Fix: Copy php.ini-production to php.ini and adjust it.

CFG-007Value depends on an environment variableinfo

${VAR} is expanded by PHP at start-up from its own environment, so a static audit cannot know the effective value; rules evaluated the literal text.

Fix: Check the variable in the PHP process environment, or use a literal value.

CFG-008Development configuration used in productionlow

The combination of display_errors, zend.assertions and mysqlnd memory statistics matches php.ini-development.

Directives display_errors, zend.assertions, mysqlnd.collect_memory_statistics

Fix: Start from php.ini-production.

CFG-009Conditional [PATH=]/[HOST=] sectioninfo
Category Configuration hygieneScope file

Directives in [PATH=...] or [HOST=...] sections apply only to matching requests under CGI/FastCGI; they are audited as separate overlays.

Fix: Verify these sections still match deployed paths and hosts.

CFG-010Deprecated directiveinfo

Deprecated directives set to a non-default value still work but emit warnings and will disappear in a future release.

Fix: Plan to remove the directive; remove it now from .user.ini/.htaccess on PHP versions affected by CVE-2026-109619.
